# modules/plans — study plans

A plan is a workspace document tagged `study-plan` (`plan.js`). It is generated by `app/api/plans/generate` (model prompt +
deterministic checks), revised/updated by the sibling routes, and built by `execute.js` (runs each step's agent and files the result).

## Rules enforced in code after the planner answers (`app/api/plans/generate/route.js`)
- `coverage.js` every concept is studied and tested; the final exam lists them all.
- `agentUse.js` every agent the learner chose is used; with the Reading Splitter every read step of an upload is a reading part.
- `dailyCap.js` no day exceeds the learner's daily minutes.
- `master.js` **Consolidated view first**: with `CONSOLIDATED_MIN_DOCUMENTS` (3) or more uploaded documents, or more than
  `CONSOLIDATED_MIN_CHARS` (150,000 characters) of uploaded material, step 1 is "Consolidated view of the resources"
  (`generate: "master"`, kind read, the plan's first day), added or moved to the front exactly once by `ensureConsolidatedStep`.
  The model is told so too (rule 14 and a `<consolidated_view>` block).
- `localPlan.js` without an OpenAI key the plan is a plain schedule built by code (read + practise each group of concepts, review,
  practice exam) and gets the same checks, so plan generation works offline.

## Building (`execute.js`)
- The master document (Summary Notes Consolidator, `STEP_RECIPES.master`) is built FIRST when `needsMasterDocument` (2+ uploads,
  the consolidated-view rule, or a `master` step). The `master` step is not run as an ordinary step: it is pointed at the master
  document (`madeAs: "master"`), so the learner reads it as step 1; every later step reads from it (`stepSourceIds`).
- A reading step (`generate: "reading"`) runs the Reading Splitter's whole-document pipeline (`spec.pipeline: "split"`) on the
  step's OWN uploaded document with `readingFocus` = the step's concepts, so the part is the material's own text about those topics.
- Plan generation itself does not cut documents into chunks: the planner sees document names and the concept map
  (`/api/concepts`); the text of a topic is cut only when a reading step is built.
